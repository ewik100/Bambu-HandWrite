## Кандидат версии 5.3.0

- Восстановлена стартовая последовательность `G21 → G90 → M83 → M400 → M400 U1` и удалены маркеры `M73`.
- Вторая остановка располагается прямо над верхним левым углом выбранного листа.
- После второй остановки G-code рисует контур на защитном A4, отъезжает за границы страницы и ждёт 50 секунд для укладки рабочего листа.
- Предполётная проверка сверяет две автоматические выдержки, геометрию контура, парковку вне бумаги и финальную последовательность `G1 Zsafe → G0 X128 Y246 → M400 → ; END`.
- Синтаксис встроенного JavaScript и отдельный пример G-code проверены в рабочем процессе изменения. Полный набор Node.js/GitHub Actions для этой редакции ещё не запускался.
- **Не подтверждено:** полный физический запуск G-code версии 5.3.0 на Bambu Lab A1. Это обновление нельзя считать доказанно исправившим преждевременное сообщение «Печать завершена» до контрольной печати под наблюдением.

## Исторический отчёт версии 5.2.0

В 5.2.0 были добавлены маркеры прогресса `M73` и удалены `M83` с начальным `M400`. В 5.3.0 эта часть откатана к более ранней структуре; причина раннего завершения на физическом принтере по-прежнему требует проверки.

## Кандидат версии 5.0.0 — проверка профиля Bambu A1

- Источник параметров профиля: официальные machine/process profiles Bambu Studio для `Bambu Lab A1 0.4 nozzle` и `0.20mm Standard @BBL A1`.
- Встроенная предполётная проверка требует обязательные ключи модели, идентификатора профиля, кинематики и рабочей области внутри `CONFIG_BLOCK`; каждый из них должен присутствовать ровно один раз.
- Модульные тесты дополнены отрицательными случаями: отсутствует `printer_settings_id` или `printable_area`.
- Проверка синтаксиса HTML/JavaScript, DOM-идентификаторов, геометрии, Z и команд пауз остаётся в прежнем наборе.

**Автоматическая проверка GitHub Actions:** run #170 (`42501651493`) завершился успешно: 32 статические проверки и 42 модульные проверки пройдены. Проверки подтверждают только программную структуру и логику, не поведение прошивки принтера.

**Ограничение:** пока не выполнен тест полного G-code на настоящем Bambu Lab A1, нельзя утверждать, что мгновенное завершение печати исправлено. Автоматические проверки подтверждают только структуру кода и логику предполётной проверки. Также они не проверяют поведение прошивки и SD-карты.

# Отчёт проверок Bambu HandWrite 5.0.0

## Регрессия масштаба строк

В `rasterText()` обнаружено отсутствие восстановления состояния Canvas после отрисовки строки. Из-за этого transform накапливался: первая строка оставалась нормальной, а следующие получали повторное масштабирование. В 4.8 каждая строка оборачивается в `withCanvasLineTransform()` с `try/finally` и `restore()`. Модульные проверки покрывают несколько последовательных строк и исключение внутри рисования.

Стандартная высота строчных букв Neucha и сброс настроек — 4,8 мм. Вторая пауза перемещает сопло на 3 мм левее и на 3 мм ниже верхнего левого угла листа; unit-тест проверяет расчёт координат и соответствие маркеру предпросмотра.

Дата сборки: 2026-11-08.

## Изменения версии 4.8

- Предэкспортная проверка блокирует скачивание, если в G-code есть не-ASCII символы, BOM, неверные переводы строк, отсутствует одна из пауз, нарушена их последовательность, неверна безопасная высота сопла при второй выдержке или отсутствует завершающая команда.
- Из сырого файла исключены необязательные `M73`-маркеры прогресса и лишние команды включения/тайм-аута шаговых двигателей.
- Вторая автоматическая остановка сохранена: сопло паркуется на заданных координатах снаружи края листа и остаётся на безопасной высоте Z до конца выдержки.

## Автоматические проверки

Для актуального исходного файла `index.html` предусмотрены два набора проверок:

- `node scripts/validate.mjs`: проверка HTML5-разметки, языка документа, синтаксиса встроенного JavaScript, уникальности HTML-идентификаторов, соответствия статических обращений к DOM, наличия обязательных файлов, ограничителей координаты Z, команд паузы и режимов перемещения, предупреждения о том, что высота сопла Z не равна фактическому зазору кончика ручки, а также отсутствия обязательной загрузки внешних JavaScript-файлов.
- `node scripts/test-unit.mjs`: модульные проверки шага строк, привязки к клеткам, верхнего отступа страницы, масштаба строчных букв, парковки сопла, автоматического подбора размера текста, ограничений Z, паузы и G-code. Для версии 4.8 проверяются значения 1, 2 и 6 клеток, размер клетки 4,5 мм, миллиметровый шаг, десятичная запятая и пределы 5–60 мм.

Эти проверки выполняются в GitHub Actions на Node.js 22.

## Что изменено в версии 4.8

- Клеточный режим задаёт количество клеток между базовыми линиями, а не пустых клеток между строками. Например, при размере клетки 5 мм: 1 клетка = 5 мм, 2 клетки = 10 мм, 6 клеток = 30 мм.
- Каждая базовая линия в клеточном режиме остаётся привязанной к сетке. При размере клетки 4,5 мм шаг в одну клетку равен 4,5 мм.
- Миллиметровый режим сохраняет точное расстояние от 5 до 60 мм, десятичная запятая поддерживается.
- Геометрический статус листа и успешная генерация G-code подсвечиваются зелёным после прохождения проверок. Замечания качества центральных линий отображаются независимо в панели качества.
- Вводящее в заблуждение предупреждение о «визуальной идеальности» удалено; для оценки формы символов остаётся доступен просмотр траектории.

## Перед первым физическим запуском

- Надёжно закрепите держатель так, чтобы он не задевал раму, кабели, вентиляторы и пластину.
- Измерьте фактический вылет кончика ручки относительно сопла и откалибруйте Z.
- Проверьте положение бумаги, зажимы и свободный проход по всей траектории.
- Выполните короткую контролируемую калибровку и постоянно наблюдайте за принтером.
- Для A1 mini, P1P, P1S, X1 Carbon и других моделей требуется отдельная адаптация координат и команд G-code.

## Как воспроизвести проверки

```bash
node scripts/validate.mjs
node scripts/test-unit.mjs
```

Статические и модульные проверки не заменяют проверку в браузере, анализ сгенерированного G-code и физический тест на принтере.
